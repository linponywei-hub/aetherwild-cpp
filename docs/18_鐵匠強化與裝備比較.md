# 鐵匠強化與裝備比較

## 原版依據與規則

查核使用者原始 Aetherwild_AI_Handoff_v0.30.1.zip 中 public/upgrade-rules.js、public/game.js 的 upgradeItem，以及 worker/character-service.mjs 的 character/enhance。只移植規則，不執行舊 JS 或 Worker。

- 本次金幣費用：ceil(220 × 1.8^目前強化等級)。
- 每次消耗鐵礦 ore ×2，包括失敗。
- 目前等級低於6時成功率100%，因此 +0→+6 保證成功。
- +6→+7 為75%；後續成功率 max(2%, 75% × 0.76^(目前等級−6))。
- 成功加一級，失敗歸零，不摧毀裝備。
- 原版無此操作上限；此移植保留目前 C++ 存檔的 +20 上限，不改既有存檔驗證。
- 武器與防具均可強化。背包可強化，倉庫裝備先取出。強化不改稀有度、需求等級或物品 ID。

## 前置條件與狀態轉移

角色存活、world 場景、已開放區域的 smith NPC，三維距離不超過8m且視線無建築遮擋，製作功能啟用。距離沿用目前 C++ NPC 服務標準，比原版檢查嚴格。

命令為 enhance，target 是背包裝備實例 ID，npc 是鐵匠 ID，expected 是確認時的強化等級，request 沿用現有請求去重。缺少或不符 expected 時拒絕；客戶端傳入 coins、chance 等欄位不能改變規則。隨機抽樣由 C++ 產生，客戶端無法選擇結果。

先驗證，再在角色副本扣款扣料及改等級，重新整理角色數值；成功後才替換角色並記錄結果事件。命令層沿用既有保存、錯誤回復與最近512筆請求收據，重試不重扣、不重抽；收據隨世界存檔恢復。此收據窗口不是無限交易歷史。

失敗操作（非鐵匠、太遠、死亡、不同場景、非本人背包物品、舊報價、金幣不足、鐵礦不足、+20）不扣款、不扣料、不改等級。有效抽樣失敗屬已完成交易，會扣款、扣料並歸零。

## 私人報價與介面

私人快照 enhancement 提供附近鐵匠、是否啟用、上限及每件背包裝備的報價：目前等級、下一級、費用、材料、成功率、能否支付、下一級屬性。其他玩家只看到已裝備武器原有的 upgrade 外觀欄位，無法讀取他人的背包、報價或比較資料。

找鐵匠按 E 可選裝備強化；製作頁也提供附近鐵匠服務。操作前確認費用、機率與失敗歸零風險，送出期間停用重複按鈕，完成後提示成功或失敗。走遠、停用服務或資源不足時停用操作，伺服器再驗證一次。

背包與倉庫顯示強化等級及實際屬性，背包提供相較同欄裝備的差值。屬性計算抽成 InventorySystem::itemStats，由戰鬥加成及畫面共用，不在 JS 複製公式。比較不含換裝造成的套裝變動；畫面明確註記。

## 驗證與限制

新增原生測試涵蓋 +6 保證成功、強制成功與失敗分支、費用、歸零、上限、距離、場景、死亡、材料與金幣不足、物品所有權、倉庫限制、舊報價、請求重送、公開資料與存檔恢復。獨立 HTTP 測試涵蓋六次保證成功、重送、偽造費用無效、錯誤資料不扣款、遠端武器強化等級及真實程序重啟。一般及 ASan/UBSan 建置與 HTTP 回歸另記於 PR。

使用目前 world-v2 保存及既有測試站，不改 SQL 或正式角色介面。免費站依然是 ephemeral 存放模式；不將一般重啟保存測試視為 Render 磁碟持久化保證。本次未完成正式平台雙玩家手動瀏覽器驗收與經濟平衡長期測試。
