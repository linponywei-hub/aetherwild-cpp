# 透明圖庫接入與製作清單

目前接入168張獨立 PNG，不代表整套已完成。完整清單在 data/artwork/manifest.json：709件裝備、285個技能、15種工具、28種採集材料與7種消耗品，共1044項；其餘876項為後續擴充圖庫，仍待製作。

## 造型與名稱

沿用使用者確認的星金鎬預覽：精細半寫實奇幻道具、金屬與皮革紋理、完整獨立物件、無文字與外框。一般裝備保持實用造型，星金與虛曜等高階工具有對應材質；技能依名稱表現招式與魔法意象。名稱採目前 C++ catalog，工具與箭矢另取既有定義，保留物品 ID，不從檔名猜測遊戲名稱。

## 格式與顯示

每件獨立存為 assets/reference/items/<ID>.png，遊戲透過 /art/items/<ID>.png 讀取。PNG 使用 RGBA，檢查確實含透明像素；沒有以黑色或棋盤格冒充透明底。遊戲版本縮為最大512×342，保留完整長寬比與 alpha，原生成圖不覆寫。

背包、角色裝備、倉庫、商店、鍛造、配方、工具、技能頁與五格技能欄共用精確 ID 圖庫索引。圖片採 contain、lazy 與 async decoding。尚未製作的項目保留原圖示，不複製其他物品圖片充數。

web/modules/artwork/artwork-index.js 只列已完成圖片；web/modules/artwork/artwork-names.js 提供既有名稱；兩者由 tools/register_artwork.py 根據 manifest 產生。manifest 的 ready/pending 是製作狀態，不是遊戲開放權限。此變更只有素材與呈現，不改 C++ 戰鬥、裝備規則或存檔。

## 接續與驗證

新增圖片時，將 id、source（本機生成圖完整路徑）與 prompt 的 JSON 陣列送入 tools/register_artwork.py。腳本驗證 PNG/alpha、產生遊戲尺寸、記錄雜湊、更新狀態與索引。續作應從 pending 項目開始，避免將已完成素材重做。

python3 tests/artwork_assets.py 檢查 RGBA、透明像素、尺寸、名稱、路徑、雜湊與圖片互異；python3 tests/artwork_http.py 使用獨立世界與實際 C++ HTTP 驗證圖片完整位元組及 image/png。Node 圖庫索引測試確認只映射已完成且存在的精確 ID，既有前端回歸亦執行。尚未完成正式平台所有介面的人工作業驗收。

## 續作：三項傳承技能（2026-11-07）

新增黑棘侵蝕（nightthorn）、風息護幕（wind）、熾焰爆流（ember）三張獨立技能插畫，使用內建圖片生成，提示詞完整記錄於 manifest。三張原圖與遊戲版均有實際 alpha 透明像素；原圖保留，遊戲版等比例縮至512×342以內。沿用既有技能頁與快捷欄精確 ID 圖庫，不改技能機制。

驗證：85張圖庫完整性、C++ HTTP逐張圖片位元組與MIME、Node全部48項測試通過；一般建置核心171、runtime1239、內容72項檢查通過。本批提交不等於線上換版，需依共同發布流程另行部署。
