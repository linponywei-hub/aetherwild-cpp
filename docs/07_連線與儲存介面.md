## HTTP共用契約（維持現有路徑）

同源HTTPS；瀏覽器不得直接決定HP、金幣、裝備所有權或存檔內容。現階段是HTTP輪詢與C++20Hz模擬，沒有WebSocket，也沒有多人跨程序協調。

| 方法與路徑 | 驗證與請求 | 成功回應 |
|---|---|---|
| GET /api/health | 不需登入 | {ok,engine,profiles,inviteRequired,cloudTest} |
| GET /api/catalog | 不需登入 | regions/items/resources/npcs/dungeons/quests/recipes/classes/skills/buildings陣列及prices物件 |
| POST /api/session | {name,profession,inviteCode?,ownerCode?}；profession=warrior/mage/ranger | {ok:true,token,player,role} |
| GET /api/state | Authorization: Bearer <token> | 本人完整player與依可見範圍過濾的世界快照 |
| POST /api/input | Bearer；{sequence,x,z,yaw,sprint?,jump?} | {ok:true} |
| POST /api/command | Bearer；{request,type,target?,npc?,count?,...命令參數} | 執行後的世界快照；不回傳登入token |

所有POST必須使用Content-Type: application/json及X-Aetherwild-Client: 1。該標頭只是現有跨站請求防護的一部分，不能冒稱完整正式CSRF／Origin驗證。請求本文上限16384 bytes；不加入GLB／圖片上傳到此JSON入口。成功HTTP200；規則／解析失敗目前HTTP400，登入失效HTTP401，格式{ok:false,error:"訊息"}。目前狀態碼由實作判斷，沒有穩定的機器錯誤碼；不要自行依中文訊息製作另一套驗證流程。

input.sequence為非負整數、同session單調遞增；舊序號忽略。x/z為[-1,1]有限數，對角線由C++正規化；yaw為弧度。世界位置及速度由C++計算。現有前端約90ms送input、160ms拉state；8秒沒有input／command便不列為在線，單純GET state不刷新在線時間；測試多人體驗要同時持續送input，不能把不在線的角色誤判為資料遺失。

command.request為1–100 bytes的不重複字串。同token重播已成功request不再執行，只回傳當前快照，並非第一次回應的逐位元副本。收據集合目前最多512個，超過後按集合順序淘汰，不是永久防重領資料庫。失敗指令回復世界狀態；發送者角色由token解析，不能以client傳入的playerId冒名。type與具體玩法參數由遊戲AI維護，部署AI不重命名。PR #1新增unequip/store_item/withdraw_item仍沿用相同command封套。

快照既有頂層：ok,now,player,role,stats,bonus,pvp,chat,xpNext,players,monsters,resources,events,objectives,online,features,invitations,lifts；party/run為條件欄位，缺少不代表錯誤。玩家與裝備ID為字串。整數財產與數量由C++ int64保存，瀏覽器對超過Number.MAX_SAFE_INTEGER的值不能保證精確；此次不改既有JSON型別，日後若改十進位字串需雙方一起遷移。

## 角色存檔契約與本部署PR變更

**本部署PR不修改角色欄位、不修改序列化、不執行角色遷移。**

- 現行權威世界檔：${AETHERWILD_DATA_DIR}/world-v2.json；未設定則<project>/runtime-data/world-v2.json。頂層version=2，保留.now、.sequence及玩家／怪物／資源／副本／獎勵／隊伍／登入映射等現有結構。
- C++保留.tmp→替換與.bak備份、10秒檢查點、成功command後保存、SIGTERM/SIGINT正常退出保存。部署程式不能直接修改JSON或發測試補給到使用者角色。
- Player私有資料涵蓋account、xp、coins、bankCoins、materials、warehouse、inventory、equipped、jobs、secrets、skills、maps、processed、gatherXp、quests與冷卻／狀態欄位。對外公開玩家視圖不能暴露背包、倉庫、session、隱藏解鎖等私有資料。
- inventory為裝備實例陣列：{id,code,rarity,required,upgrade}；equipped為slot字串→實例ID物件，必須參照該玩家背包。材料warehouse為code→數量，不能改成裝備陣列。
- PR #1的warehouseItems是另加可選裝備陣列，缺欄位預設空；ID不可與背包重複，不能被equipped引用。這屬於既有遊戲分支變更，不是本部署PR資料遷移。
- CLI角色檔：main為AWCHAR 1；PR #1寫入AWCHAR 2並相容讀取1/2。不要混用CLI角色檔與world-v2.json，也不要讓不支援新版的程式覆寫新版存檔。
- runtime-data含session映射，不得提交Git或放下載包。部署前後有需要的存檔轉移必須用受保護流程，並先做備份與dry-run。
- Free服務的本機資料可能在休眠／重啟／重建後消失；目前尚無持久磁碟、資料庫或外部備份。不能因API顯示save成功而承諾永久保存。
