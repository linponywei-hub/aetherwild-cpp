# 資料模型與不變條件

本文件區分「已在 C++ 模型存在」與「下一階段才加入」。所有型別以 `domain.hpp`／`social.hpp` 為準，未完成欄位不會假裝已經可用。

## ID 與資料層次

| 名稱 | 例子 | 用途 |
|---|---|---|
| 帳號 ID | `local:p` | 登入與權限；本機模式不等於 Google 登入 |
| 角色 ID | `p` | 一個角色的永久身分 |
| 裝備定義 ID | `ironblade` | 所有精鐵長劍共用的名稱、基礎屬性、武器類型 |
| 裝備實例 ID | `item_1` | 某一把長劍，保存稀有度、強化與既定需求等級 |
| 怪物實體 ID | `guard_12` | 一次生成的怪物，不等於怪物種類 |
| 首領定義 ID | `boss_cinder` | 世界王內容定義 |
| 副本定義／執行 ID | `ruins`／`run_5` | 副本內容與一次通關進度分開 |
| 獎勵事件 ID | `reward:boss_12:p` | 同一獎勵只可處理一次；不可截斷 |

目前 `Id` 是 `std::string`，由領域服務檢查參照。正式分散式環境需改用伺服器產生的 UUID／ULID 等全域 ID；目前單程序序列 ID 不可當成跨伺服器 ID 生成器。

## 玩家 Player

| 欄位 | 型別 | 規則 |
|---|---|---|
| id／accountId／name | Id／Id／string | 角色身分與帳號分開，名稱不可空白 |
| profession | Id | 必須參照職業目錄 |
| level／xp | int／int64 | 本次新核心上限 Lv.100；XP 不可為負 |
| coins／bankCoins | int64 | 不可為負，所有數量操作檢查溢位；bankCoins 目前只有模型，未開銀行交易 |
| vitals | Vitals | hp/maxHp、mp/maxMp、stamina/maxStamina |
| position／scene／lastCity | Vec3／Id／Id | 座標必須有限值，場景與最後城鎮分開 |
| materials／warehouse | map<Id,int64> | 材料與消耗品堆疊，不與裝備實例混用 |
| inventory | vector<ItemInstance> | 每件裝備唯一 ID |
| equipped | map<Slot,Id> | 參照背包實例，同一實例不可重複套裝計數 |
| tools／gatherXp | map<Id,int>／int64 | 工具種類與階級、採集熟練度 |
| jobs／secrets | set<Id> | 已取得職業、已發現隱藏條件；對外快照須依角色過濾 |
| learnedSkills／unlockedMaps | set<Id> | 技能已串接；地圖只有模型，購圖待作 |
| quests | map<Id,QuestProgress> | 計數不超過需求；領取旗標不可重設 |
| processedRewards | set<Id> | 防重領；角色存檔會保存 |
| attackReady／skillReady | 時間／map | 伺服器時鐘，不接受客戶端傳入已冷卻 |
| shield／shieldUntil | double | 護盾與到期時間 |
| regenReady／sprintLocked／staminaUpdatedAt | 時間／bool／時間 | 體力延遲回復、20%解除鎖定、避免重複 tick |

`Player::attackIntent()` 檢查自身是否存活；`CombatSystem::attack()` 才負責完整攻擊流程。`Player::receiveDamage()` 與 `Monster::receiveDamage()` 共用生命值扣除不變條件。

資料結構目前為核心內部可修改狀態，方便測試安排情境。未來客戶端不可直接取得可寫 World，必須透過命令處理器與唯讀快照。

## 裝備與武器

| 型別／欄位 | 內容 |
|---|---|
| ItemDefinition | id、name、slot、weapon、基礎 Stats、requiredLevel、set |
| ItemInstance | id、definition、rarity、requiredLevel、upgrade |
| Slot | Weapon、Armor、Helm、Boots、Charm |
| WeaponKind | None、Sword、Staff、Bow |
| Stats | hp、mp、attack、defense、crit、speed |
| Rarity | Common、Rare、Epic、Excellent、Legendary、Mythic、Immortal |

武器的「攻擊力」放在定義；稀有度與強化屬於實例。穿戴前驗證擁有權、實例需求等級與職業武器類型。角色衍生能力由職業、等級、裝備與套裝算出，不把攻擊力當作客戶端可任意寫回的欄位。

原始獲得需求等級保存於實例，後續調整目錄不會悄悄更改既有裝備需求。耐久度、修理、詞綴、交易鎖與綁定狀態是後續模型擴充，尚未實作。

## 怪物、採集、任務、副本與經濟

| 模型 | 已有主要欄位 | 不變條件 |
|---|---|---|
| Monster | id、definition、level、position、scene、Vitals、attack、defense、boss、contribution、rewardIssued、frozenUntil | HP 歸零只建立一次獎勵；只對有效命中紀錄貢獻 |
| ResourceNode | id、definition、position、scene、readyAt、reservedBy、completeAt | 一次只容許一人預約；完成時再次檢查距離、工具與存活 |
| ResourceDefinition | family、tool、tier、proficiency、xp、seconds | 木材 family=wood，需斧；樹枝與石頭可徒手 |
| Recipe | id、output、tier、cost、station、equipment、count | 先驗證城市、NPC、材料，再一次扣款與生成 |
| QuestDefinition | type、target、npc、level、count、coins、xp | 不直接信任客戶端的進度數字 |
| QuestProgress | count、claimed | 先完成再回原委託 NPC 領獎 |
| DungeonRun | definition、player、members、guardsRemaining、objectives、interacted、bossDead、chestClaimed、returnPositions | 機關不得重算，首領被前置目標鎖定，寶箱只能領一次 |
| Reward | id、player、coins、xp、materials、items | 領取者需一致，重播事件不再加獎品 |
| RegionDefinition | id、name、center、radius、level、city、wilderness | 0.2.0依實際分層樓板判斷，高架城下不會直接當城市 |
| NpcDefinition | id、region、name、role、position | 依已知服務角色與權威座標檢查距離 |
| Party | id、leader、members、invited | 最多5人、一人一隊、需要邀請、隊長離開要遞補 |
| Account／SessionState | role、accounts、parties、memberParty、pvpEnabled | 工作站以測試Session綁定角色；目前沒有正式OAuth實作 |

## 時間、數量與保存

- 模擬時間採 double 秒，單次 `advance` 限制 0–10 秒；實際移動每次最多1秒。時鐘不由外部玩家決定。
- 金幣、材料、XP 使用 64 位整數；HP／MP、距離、冷卻使用有限浮點數。
- 新本機角色格式為 `AWCHAR 1`，完整解析驗證後才替換角色；舊檔另存 `.bak`。這不是正式站 SQL 存檔匯入器。
- 不允許在副本內存角色，避免保存失去對應 Run 的場景。這是舊CLI角色檔的限制。0.2.0工作站另有world-v2.json，會保存世界王、獎勵、共享Run、隊伍、角色、權限、請求去重與升降狀態。
- 所有正式角色、世界獎勵、版本鎖與稽核，後續必須由交易式 repository 保存。參見 `ports.hpp` 與 `docs/05_接續實作.md`。

## 0.2.0新增模型

Motion保存權威移動方向、序號、朝向、垂直速度、接地、滯空、最高點與升降乘坐狀態。Lift保存起點、終點、開始時間與移動狀態。LocalProfile保存測試Session綁定與去重請求ID，不能出現在對其他玩家的快照或下載包。Player新增arrowHasteUntil；DungeonRun新增members、chestClaimed與各玩家returnPositions。
