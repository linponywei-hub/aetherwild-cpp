# 連線同步效能修正

分支：ai/connection-performance；本次只修改HTTP傳輸、前端同步與相關測試。不改遊戲規則、地圖、職業、角色存檔或資料庫。

## 診斷

使用者回報「走路停頓或瞬移」，而非轉動鏡頭也卡。Render當時CPU約0.002–0.003核，記憶體約4–8MB，沒有資源飽和證據；HTTP延遲指標沒有資料，因此尚不能量化使用者端RTT。原版前端移動輸入與state輪詢分開，約11+6次請求/秒，且較晚抵達的舊回應可能覆蓋新狀態。

## 介面增量（原用法維持相容）

POST /api/input接受可選snapshot:true。省略／false仍回傳{ok:true}；true先套用相同輸入驗證，再回傳與GET /api/state相同的快照。驗證與角色綁定不變。

所有含player的HTTP成功回應增加可選_sync:{epoch:string,sequence:integer}。epoch每次原生HTTP程序啟動重新建立，sequence按伺服器產生回應的順序遞增。這是傳輸中繼資料，不寫入world-v2.json，也不取代遊戲事件ID或command.request。

前端使用web/modules/network/network-sync.js的SnapshotOrder，丟棄同epoch的重複／舊sequence；接受新epoch重啟序號，拒絕已退役epoch的遲到回應。舊伺服器缺_sync時退回now時間順序檢查。

輸入改用snapshot:true並更新畫面；狀態正常更新時略過額外GET輪詢，超過1秒沒有快照才以原GET路徑補查。放開按鍵／視窗失焦時嘗試立即送最新輸入；已有請求進行時沿用下次既有週期，不平行累積移動請求。沒有加入client自行決定位置、延長伺服器輸入有效期或改變碰撞判定。

## 修改檔案與整合

- apps/workstation.cpp：可選輸入快照與_sync標記。
- web/modules/core/client.js：單次移動往返、順序過濾與復原輪詢。
- web/modules/network/network-sync.js：獨立純傳輸順序管理。
- tests/workstation_http.py：舊／新input格式、身份與序號驗證。
- tests/network_sync.test.mjs：同tick回應亂序、程序重啟遲到回應、舊伺服器相容。
- 本文件。

共享檔案apps/workstation.cpp與web/modules/core/client.js需逐段合併，不可整檔覆蓋遊戲AI的內容。以目前線上版本commit a5b533b54785a85957a0495d5c7dc1085dc8d9a1為基準，透過獨立PR合入目前追蹤的測試版本分支，再由Render手動部署；不直接編輯遊戲分支。
